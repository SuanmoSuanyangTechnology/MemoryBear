# 工作空间统一记忆配置后端改造设计

## 1. 目标

- 运行时唯一生效的记忆配置统一为工作空间当前生效记忆配置。
- `agent` 保留记忆启用能力，取消应用自身指定 `memory_config_id` 的能力。
- `memory-read` / `memory-write` 节点只保留业务参数，不再决定具体记忆配置。
- 导入、导出、发布、回滚、反射、终端用户绑定等链路统一按工作空间生效配置执行。

## 2. 生效规则

### 2.1 Agent

- `agent` 继续使用现有 `memory.enabled` 开关。
- `memory.enabled = false` 时，不触发记忆能力。
- `memory.enabled = true` 时，直接使用工作空间当前生效记忆配置。
- `memory.memory_config_id`、`memory.memory_content` 不再参与运行时决策。

### 2.2 Workflow

- 工作流是否触发记忆能力，仅由 `memory-read` / `memory-write` 节点是否被执行决定。
- 只要执行到记忆节点，即使用工作空间当前生效记忆配置。

### 2.3 Memory Node

- `memory-read` 保留字段：`message`、`search_switch`。
- `memory-write` 保留字段：`message`、`messages`。
- 节点 `config_id` 改为兼容字段：允许旧数据读入，保存时不再输出，运行时一律忽略。

## 3. 配置结构

### 3.1 Agent

```json
{
  "memory": {
    "enabled": true
  }
}
```

### 3.2 Workflow

```json
{
  "nodes": [
    {
      "id": "memory_write",
      "type": "memory-write",
      "name": "记忆写入",
      "config": {
        "messages": [
          {
            "role": "user",
            "content": "明天吃KFC"
          }
        ]
      }
    },
    {
      "id": "memory_read",
      "type": "memory-read",
      "name": "记忆读取",
      "config": {
        "message": "明天吃什么",
        "search_switch": "2"
      }
    }
  ],
  "edges": [],
  "variables": [],
  "execution_config": {},
  "triggers": []
}
```

## 4. 改造范围

### 4.1 Schema

涉及：

- `api/app/schemas/app_schema.py`
- `api/app/schemas/workflow_schema.py`
- `api/app/core/workflow/nodes/memory/config.py`

改造：

- `agent` 保留 `memory.enabled`，废弃 `memory.memory_config_id`。
- `MemoryReadNodeConfig.config_id`、`MemoryWriteNodeConfig.config_id` 由必填改为可选兼容字段。

### 4.2 Node 执行

涉及：

- `api/app/core/workflow/nodes/memory/node.py`

改造：

- `MemoryReadNode.execute()` 不再读取 `self.typed_config.config_id`。
- `MemoryWriteNode.execute()` 不再读取 `self.typed_config.config_id`。
- 节点执行时基于 `workspace_id` 解析工作空间当前生效记忆配置，再将真实 `config_id` 传入 `MemoryService`。
- 节点调试信息中的 `config_id` 记录实际解析出的工作空间配置 ID。

### 4.3 记忆配置服务

涉及：

- `api/app/services/memory_config_service.py`

改造：

- 工作空间生效配置统一由 `get_workspace_default_config(workspace_id)` 或等价入口返回。
- `extract_memory_config_id(app_type, config)` 不再为 `workflow` / `pure_workflow` 扫描节点 `config_id`。
- `_extract_memory_config_id_from_workflow()` 删除或废弃。
- `get_config_with_fallback()` 的 fallback 统一落到工作空间生效配置。

### 4.4 发布、回滚、终端用户绑定

涉及：

- `api/app/services/app_service.py`
- `api/app/services/memory_agent_service.py`

改造：

- 发布、回滚时不再从工作流节点提取 `config_id`。
- `workflow` / `pure_workflow` 不再基于节点配置批量更新 `end_user.memory_config_id`。
- `get_end_user_connected_config()` 统一优先返回工作空间当前生效配置。
- 历史 `end_user.memory_config_id` 不再覆盖工作空间统一配置。

### 4.5 DSL 导入导出

涉及：

- `api/app/services/app_dsl_service.py`
- `api/app/services/workflow_import_service.py`

改造：

- 导出工作流时不再输出记忆节点 `config_id`。
- 导入旧 DSL 时允许 `config_id` 存在，但导入后仅保留节点业务参数。
- `_resolve_workflow_memory()` 及工作流节点 `config_id` 解析逻辑删除或改为仅兼容告警，不再回写实际配置。

### 4.6 其他链路

涉及：

- `api/app/services/memory_reflection_service.py`
- 其他从发布配置扫描工作流记忆节点的逻辑

改造：

- 不再通过工作流节点提取记忆配置。
- 统一直接读取工作空间当前生效记忆配置。

## 5. 兼容规则

- `agent` 历史 `memory.memory_config_id` / `memory.memory_content` 允许继续读入，但不再影响运行结果。
- 工作流节点历史 `config_id` 允许继续存在于存量数据中，但不再影响运行结果。
- 保存、重新导出、发布后不再输出节点 `config_id`。
- 存量 `end_user.memory_config_id` 不再覆盖工作空间当前生效记忆配置。

## 6. 接口约定

### 6.1 Agent 接口

返回和保存保留：

```json
{
  "memory": {
    "enabled": true
  }
}
```

### 6.2 Workflow 接口

返回和保存不新增工作流级记忆字段：

```json
{
  "nodes": [],
  "edges": [],
  "variables": [],
  "execution_config": {},
  "triggers": []
}
```

### 6.3 节点详情接口

- 节点详情只返回节点业务配置。
- 不返回“当前节点使用哪个记忆配置”的独立字段。
- 实际生效记忆引擎信息统一从工作空间当前生效记忆配置获取。

## 7. 测试范围

### 7.1 Agent

- `memory.enabled = false` 时，不触发记忆能力。
- `memory.enabled = true` 时，使用工作空间当前生效记忆配置。
- 历史 `memory_config_id` / `memory_content` 不影响最终运行配置。

### 7.2 Workflow

- 执行到 `memory-read` / `memory-write` 节点时，统一使用工作空间当前生效记忆配置。
- 未执行到记忆节点时，不发生记忆读写。
- 节点携带历史 `config_id` 时，运行结果不依赖该值。

### 7.3 DSL 与发布链路

- 导出结果中不再出现节点级 `config_id`。
- 导入包含旧 `config_id` 的 DSL 后，工作流仍只取工作空间当前生效记忆配置。
- 发布、回滚 `workflow` / `pure_workflow` 时，不再扫描节点 `config_id` 更新 `end_user.memory_config_id`。

### 7.4 兼容链路

- `memory_reflection_service.py` 等旁路不再依赖工作流节点 `config_id`。
- 存量 `end_user.memory_config_id` 不覆盖工作空间统一记忆配置。

## 8. 最终规则

- 实际生效的记忆配置只有一个来源：工作空间当前生效记忆配置。
- `agent` 保留 `memory.enabled`。
- `workflow` 不新增记忆开关，不新增工作流级 `memory_config_id`。
- `memory-read` / `memory-write` 节点不再决定具体记忆配置。
- 工作流执行到记忆节点时，统一使用工作空间当前生效记忆配置。
